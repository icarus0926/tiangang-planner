# 领域模型与行为契约

## 核心对象

### Goal（年度目标）

`goals` 是年度展示和聚类锚点，字段包括名称、领域、成功标准、年份、手工进度、状态和排序。删除目标时，相关任务不会删除，外键会把 `tasks.goal_id` 置空。

### Task（任务节点）

`tasks` 的每一行都是完整任务节点。`parent_id` 指向同表父节点；根节点的 `parent_id` 为 `NULL`。所谓“步骤”已经统一为子任务，因此子节点也能编辑、再拆分、排期、挂靠、归档和完成。

关键字段：

| 字段 | 含义 |
| --- | --- |
| `parent_id` | 树结构；只用于挂靠，不承担排序 |
| `goal_id` | 年度目标归属；可为空 |
| `kind` | 分类/标签；同一子树展示时通常继承根节点分类语义 |
| `priority` | 可选优先级；不是任务池分组依据 |
| `status` | 生命周期状态，见下文 |
| `month` | 计划归属月份，格式 `YYYY-MM` |
| `start_date` / `end_date` | 甘特排期，格式 `YYYY-MM-DD` |
| `sort` | 同层展示顺序；允许小数 |
| `done_at` | 完成历史日期；完成时写入，重开时清空 |
| `note` | 备注或迁移信息 |

### Execution（每日执行）

`executions` 表示某天的待办，有两种互斥来源：

- `task_id`：引用正式任务；同一任务同一天只允许一条记录。
- `text`：自由文本琐事，不污染任务树；显式升格后创建 pool 任务并改为关联该任务。

勾选关联执行记录时，只有叶子任务与任务完成状态联动；关联非叶子任务只记录当天打卡，避免一次打卡意外完成整个项目。

### Tag（分类）

标签数组以 JSON 存在 `meta(key='tags')`。`其他` 是前端兜底分类，不进入自定义数组。标签名称去空白、去重，最多 30 个，每个最多 12 个字符。

## 任务状态

当前状态集合：

| 状态 | 语义 |
| --- | --- |
| `goal` | 年度目标下产生、尚未放行到任务池的根任务 |
| `pool` | 未正式分配的任务池任务 |
| `planned` | 已进入计划流程；可能只有月份，也可能已有日期 |
| `done` | 已完成；`done_at` 应有值 |
| `archived` | 软删除，不进入默认数据集 |

创建根任务时的推导顺序：有 `month` 或 `start`，或存在父任务 → `planned`；只有 `goal_id` → `goal`；其他裸任务 → `pool`。接口允许显式传 `status:'pool'` 作为创建例外。

重开或恢复时，每个节点按自身字段回落：

```text
有 month / start_date / parent_id  -> planned
否则有 goal_id                    -> goal
否则                              -> pool
```

## 字段点亮与时间尺度

同一任务不会复制为年任务、月任务、周任务和日任务。页面只是按字段投影：

| 字段/关系 | 点亮的视图 |
| --- | --- |
| `goal_id` | 年度目标中的任务簇 |
| `month` | 对应月的规划池 |
| 日期与 7 天窗口相交 | 周计划 |
| `start_date` / `end_date` | 月/周甘特条 |
| 当天 `execution` | 每日待办 |

周维度纯粹由周一至周日的窗口计算，没有 `week` 字段和周任务表。在周页面新建任务只是直接写入本周日期。

`month` 表示计划归属，不表示完成月份。完成历史一律以 `done_at` 分组；顺延月份不能改写已经发生的完成历史。

## 任务树不变量

1. 一个节点最多一个父节点，但层深不设业务上限。
2. re-parent 不得把任务挂到自身或任何后代，否则形成环。
3. 排序和挂靠彼此独立：同层拖动只改 `sort`；明确“挂到”操作才改 `parent_id`。
4. 父任务移动甘特条时，所有已有日期的后代按真实日历日平移相同天数。
5. 无日期父节点若存在有日期后代，甘特图显示后代最早到最晚日期形成的虚线信封；它是派生展示，不写入父节点日期。
6. 归档和恢复作用于整棵子树。默认读取排除 `archived`。

## 完成与进度

所有节点都允许被用户勾选：

- 勾选未完成节点：节点及全部非归档后代一起设为 `done`，写入当天 `done_at`。
- 取消已完成节点：整棵子树按字段回落到 `planned`、`goal` 或 `pool`，并清空 `done_at`。
- 叶子变化后，祖先逐级重算；所有非归档直接子节点完成时父节点自动完成，否则已完成父节点自动重开。
- 新增未完成子节点到已完成父节点时，父链应自动重开。

进度是“完成叶子数 / 总叶子数”。服务端 `/api/data` 动态返回每个节点的 `leaves` 与 `done_leaves`。非叶节点自身状态不额外计为叶子，避免重复计数。

## 删除、归档和恢复

- `DELETE /api/task/:id` 默认把节点及其后代改为 `archived`。
- `DELETE /api/task/:id?hard=1` 只接受已经归档的根节点，并依赖外键级联物理删除子树。
- `POST /api/task/:id/restore` 可恢复 `archived` 或 `done` 子树，并清空完成状态。
- 删除 execution 是物理删除单条待办；删除 goal 是物理删除目标但保留任务。

## 顺延

- 月顺延按与规划池一致的“本月相关”规则选取最高未完成任务簇：显式 `month=from`，或 `month` 为空但自身/未完成后代日期与本月相交。簇根切换到新月份，簇内仍明确归属原月的未完成节点一并切换；不改变甘特日期、已完成子任务或 `done_at`。
- 日顺延只移动指定日期未完成的 execution，不改变已完成记录。
- 两种顺延均在服务端事务内批量执行并写审计。
