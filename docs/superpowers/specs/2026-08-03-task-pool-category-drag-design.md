# 任务池分类整块拖拽设计

## 目标

任务池的分类块支持上下拖动排序。用户不需要寻找单独的拖拽手柄，直接按住分类名称所在的左侧分类区域拖动；分类标题、任务卡、已展开的子任务面板和分类添加框作为一个整体换位，刷新后顺序保持。

## 交互契约

1. 每个标签分类渲染为一个独立的 `.pool-group`，内部包含当前 `.pool-layer`、展开面板和添加框。
2. 分类名称所在的左侧分类区域是拖动起点，鼠标按下并移动即可拖动整组；不新增六点、箭头等专门手柄。
3. 拖动中的整组降低透明度，经过目标分类上半区/下半区时显示对应的顶部/底部插入线。
4. 松开后立即按新顺序重绘，并通过现有 `POST /api/tags` 保存标签数组；页面刷新后顺序不变。
5. `其他` 是未知分类的兜底项，固定在最后，不允许被拖走；其他分类可拖到它之前。
6. 点击分类名仍不触发额外动作，只有形成拖动手势才排序。

## 与现有拖拽的隔离

- 任务卡 `.pcard[data-pdrag]` 继续负责“拖到其他分类改变任务标签”。
- 分类排序只从左侧 `.pl-lab` 开始，不从任务卡、按钮、输入框或展开的子任务区域开始，因此两类拖拽不会抢事件。
- 分类拖动状态使用 `dragged={kind:'tagorder',tag}`；任务卡保持 `kind:'pooltag'`，规划池和甘特的其他 `dragged.kind` 不变。
- 分类排序只改标签数组顺序，不修改任何任务的 `kind`、`sort`、月份、排期或树关系。

## 数据流

```text
拖动分类左侧区域
  -> 计算目标分类和前/后位置
  -> 对 TAGS（排除“其他”）做稳定重排
  -> POST /api/tags { tags: reordered }
  -> reload() 读取服务端顺序
  -> renderPool() 按新顺序重绘整组
```

现有 `meta(key='tags')` 已按 JSON 数组保存顺序，不新增表、字段或 API。

## 失败处理

- 拖到自身或最终顺序未变化时不发请求。
- 保存失败时显示错误提示并重新加载服务端数据，避免界面顺序和持久化顺序分叉。
- `dragend` 无论成功与否都清理透明度和插入线。

## 验收

1. 改动前，分类左侧区域不能拖动分类，浏览器验收应失败。
2. 将“投资”拖到“工作”上方后，整个投资分类块移动到工作之前。
3. 刷新页面，顺序仍保持。
4. 把一张任务卡拖到另一个分类，仍然只修改该任务分类，不移动分类块。
5. 分类区的新增、改名、删除、展开子任务和编辑按钮仍可用。
6. “其他”保持最后，其他分类可拖到它之前。
7. `npm test` 全部通过，浏览器控制台无错误。

## 非目标

- 不改变月度规划池、甘特或大纲的排序。
- 不增加分类层级、折叠或跨页面分类配置。
- 不新增拖拽手柄、第三方拖拽库或数据库表。
