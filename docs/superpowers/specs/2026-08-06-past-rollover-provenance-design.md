# 全量过往任务顺延与来源标记设计

## 目标

在每日、每周、每月页面分别增加“过往未完成 → 今天 / 本周 / 本月”按钮，一次追回当前周期之前的全部未完成事项。顺延不仅改变页面归属，也同步平移实际排期，并在对应页面持续显示任务最初来自哪天、哪周或哪月。

现有“未完成顺延明天”和“未完成顺延到下月”按钮保留；新按钮解决跨过多个周期后仍滞留在历史窗口中的遗漏任务。

## 已确认的产品语义

1. 范围是当前周期之前的**全部**未完成事项，不限于上一周期。
2. 来源使用**首次来源**：`7月 → 8月 → 9月` 始终显示“来自7月”。
3. 顺延时实际排期同步进入当前周期，不只改变显示归属。
4. 部分完成的任务簇可以顺延；已完成节点保留原日期、`done_at` 和完成历史，只移动未完成部分。
5. 年度目标、无日期且未分配的普通任务池任务不属于“过往任务”，不会被按钮拉取。

## 方案选择

采用“显式首次来源字段 + 后端事务批量顺延”。来源不能从当前日期或审计日志临时反推，因为多次顺延后当前日期已经失去原始信息；独立顺延历史表虽然信息最完整，但本轮只需要首次来源，复杂度不必要。

## 数据模型与兼容迁移

`tasks` 增加：

- `rollover_origin_week TEXT`：首次来源周的周一，ISO 日期。
- `rollover_origin_month TEXT`：首次来源月份，`YYYY-MM`。

`executions` 增加：

- `rollover_origin_date TEXT`：首次来源日期，ISO 日期。

字段只在第一次跨周期顺延时写入，后续使用 `COALESCE(已有来源, 本次来源)`，不覆盖首次来源。完成、重开、手工改名、挂靠和恢复均保留来源字段。

任务簇顺延时，来源字段写入被选中的簇根以及实际移动的未完成节点；子任务自身没有来源时，前端可沿父链读取最近的来源。这样无日期父任务也能在列表和信封甘特条上显示来源，同时不会给未移动的已完成子任务制造虚假来源。

当前 `CREATE TABLE IF NOT EXISTS` 无法给旧库补列，因此 `db.open()` 在执行基础 schema 后通过 `PRAGMA table_info` 检查并按需执行幂等 `ALTER TABLE ... ADD COLUMN`。不引入新表，也不改变已有数据。

## API

新增：

```http
POST /api/rollover/past
Content-Type: application/json

{ "scope": "day",   "to": "2026-08-06" }
{ "scope": "week",  "to": "2026-08-03" }
{ "scope": "month", "to": "2026-08" }
```

- `day.to` 必须是 ISO 日期。
- `week.to` 必须是目标周周一。
- `month.to` 必须是 `YYYY-MM`。
- 前端始终传真实今天、本周周一和本月，不使用当前浏览窗口伪装“当前周期”。
- 整批操作在一个 SQLite 事务中完成；任何冲突或校验失败都回滚。
- 返回 `{ ok, count, roots, merged }`，其中 `count` 是实际移入当前周期的事项数，`roots` 是移动的任务簇根 ID，`merged` 是每日关联待办去重合并数。

原 `POST /api/rollover` 保持兼容，继续服务“指定一天→下一天”和“指定月份→下一月”。

## 每日顺延

候选集合是 `executions.date < to AND done=0` 的全部记录。

- 自由文本执行项直接把 `date` 改为今天，并以旧记录的 `rollover_origin_date` 或旧 `date` 作为首次来源。
- 任务关联执行项受 `UNIQUE(task_id,date)` 约束。若今天尚无同任务记录，直接移动；若今天已有记录，则保留今天记录，将最早首次来源合并到今天记录，并删除被合并的历史未完成重复记录。
- 合并和删除全部写审计；不改关联任务本身的甘特日期。
- 今日待办显示 `来自 8月2日`；悬停显示完整 ISO 日期。

## 每周顺延

周仍是纯 7 天窗口，不新增持久化 `week` 业务字段。候选任务必须有可计算的有效日期范围，且未完成有效范围的结束日期早于目标周周一。

1. 沿任务树聚合为最高相关未完成任务簇，避免父子重复移动。
2. 来源周取该簇最早未完成排期节点所在周的周一；若已有 `rollover_origin_week` 则沿用。
3. 计算 `目标周一 - 来源周一` 的整天差，将簇内所有未完成且有日期的节点平移相同天数。
4. 保留星期位置、持续天数、父子相对排期和排序；已完成节点不动。
5. 簇内被移动节点的计划月份同步设为目标周周一所在月份。若跨月且尚无月来源，记录原计划月份到 `rollover_origin_month`，使月度页也能解释来源。

本周任务列表和本周甘特显示 `来自 7月第4周`；悬停显示原周的周一至周日日期范围。

若任务已经与本周有日期交集，它本来就属于本周，不再重复顺延。

## 每月顺延

候选任务满足以下任一条件，并且是未完成状态：

- 显式 `month < to`；
- 有效日期范围结束于目标月第一天之前。

处理规则：

1. 沿树聚合为最高相关未完成任务簇；当前月份中的父任务不会因一个历史子任务而被无条件整体重排，只移动实际过期的未完成分支。
2. 来源月优先取已有 `rollover_origin_month`，否则取旧 `month`；没有月份时取最早未完成排期节点的月份。
3. 无日期任务只把 `month` 改为本月。
4. 有日期任务以簇的最早未完成开始日期为锚点，将锚点平移到目标月的同日；目标月没有该日时夹到月末。随后对簇内全部未完成日期节点加同一个天数差，因此持续天数和节点相对位置不变。
5. 已完成子任务不移动，`done_at` 不变。

本月规划池、月度甘特和月度大纲显示 `来自 7月`；悬停显示完整来源月份。

## 前端交互

### 月度规划

- 在“本月规划池”标题右侧新增主按钮 `过往未完成 → 本月`。
- 现有 `未完成顺延到下月` 保留为次要按钮。
- 点击新按钮始终以真实本月为目标；成功后切回本月并刷新。

### 周计划

- 在页面头部“添加周任务”旁新增 `过往未完成 → 本周`。
- 成功后切回真实本周并刷新周甘特和任务列表。

### 每日执行

- 在“当日待办”标题处新增 `过往未完成 → 今天`。
- 现有 `未完成顺延明天` 保留。
- 成功后切回今天并刷新待办。

所有按钮点击前显示确认信息，明确候选范围是“全部过往未完成”；返回 `count=0` 时提示“没有需要顺延的过往任务”。请求进行中按钮禁用，防止重复提交。

## 来源徽章

使用紧凑的中性色 `originchip`，不与任务分类标签、优先级或完成状态混色：

- 日：`来自 8月2日`
- 周：`来自 7月第4周`
- 月：`来自 7月`

徽章只出现在对应执行页面：每日待办、周任务/周甘特、月度规划池/月甘特/月大纲。任务池和年度目标页不显示，避免无关信息拥挤。已完成区域若该项有来源仍保留徽章，以便回看任务最终从哪里顺延而来。

## 错误处理与审计

- 非法 `scope`、日期格式或非周一的周目标返回 400。
- 事务内发生唯一键冲突、日期计算错误或数据库错误时整批回滚并返回 500。
- 审计动作使用 `rollover-past-day`、`rollover-past-week`、`rollover-past-month`，记录目标周期、移动数量、根 ID、合并数量和首次来源摘要。
- 不删除任务；每日重复关联执行记录的合并删除必须在审计中留下旧 ID 与保留 ID。

## 测试与验收

### 数据层与 API

- 旧数据库打开后自动补齐三个来源列，重复启动不报错。
- 日：跨多天全部拉取、首次来源不覆盖、自由文本移动、关联任务目标日冲突合并、完成项不动。
- 周：跨多周全部拉取、保留星期与时长、父子同差平移、已完成子节点不动、当前周相交任务不重复移动。
- 月：显式旧月份与纯日期旧任务都拉取、月末夹取、保持持续天数和相对位置、部分完成任务簇正确处理。
- 三个 scope 都验证事务审计、空结果和非法参数。
- 原 `/api/rollover` 日/月测试继续通过，证明向后兼容。

### 浏览器

- 三个页面都能看到新按钮，旧按钮仍存在。
- 顺延后立刻进入今天/本周/本月，甘特和列表同步变化。
- 来源徽章出现在对应列表、甘特、大纲和完成区，长名称下不遮挡现有按钮。
- 刷新页面后排期和首次来源保持。
- 快速重复点击不会产生重复移动或重复执行记录。

## 非目标

- 本轮不提供完整顺延路径时间线，只保留首次来源。
- 不增加周期任务或持久化 week 字段。
- 不自动顺延已完成任务，不改变完成历史。
- 不移除现有向下一天、下一月顺延功能。
