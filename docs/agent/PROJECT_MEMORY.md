> 最近核对：2026-08-03。这里记录会影响后续开发判断的当前事实；稳定业务规则以其他 `docs/agent/` 文档为准。

- 项目：天罡日程 2.0 / `tiangang-planner`。
- 仓库：`https://github.com/icarus0926/tiangang-planner`，公开，默认分支 `main`。

- Notion 已退出运行链路；迁移脚本仅用于一次性导入。

## 已确认的产品决策

1. 任务与步骤统一为无限递归任务树，树根可在年、月、周、日任意尺度产生。
2. 周计划没有持久化层级，只是 7 天日期窗口。
3. 父任务也可以勾选；勾父节点时所有子孙一起完成，取消时整树重开。子节点完成变化继续向上冒泡。
4. 所有时间维度都要有完成记录区；统计使用 `done_at`，完成甘特行划线并沉底。
5. 任务池按可编辑标签分类，不按优先级分类。已分配任务用深色区分，任务卡可跨分类拖动改标签；按住左侧分类名称可把标题、卡片、展开区和添加框整块换序，顺序保存到 `meta.tags`，`其他` 固定最后。
6. 年度目标下的新任务先留在目标区，用户显式点击 `→ 池` 后才进入月度任务池流程。
7. 本月规划池既显示已排进甘特的任务，也允许直接增删改、添加子任务、挂靠和退回。
8. 月/周共用甘特交互：真实日期拖动、父条带整树移动、信封/幽灵条、同层排序与挂靠隔离。
9. 总览任务图要保持簇较分散、显示全部子节点名称、标签尽量不遮挡；拖父节点时子节点保持簇形随动。
10. 月度“未完成顺延到下月”按规划池可见的最高未完成任务簇处理，包含仅靠日期进入本月且部分完成的任务；保留原排期和完成历史。

## 已知技术债与边界

按优先级记录，修复时要补测试并更新本文件：

1. **状态回落边界**：`bubbleDone()` 自动重开祖先时固定写 `planned`；execution 取消完成叶子时也固定写 `planned`。对原本应回到 `goal` 或 `pool` 的根节点可能分类错误，应复用统一的状态推导函数。
2. **批量前端操作非原子**：标签改名/删除、父甘特移动、整树取消日期、批量排序是浏览器顺序 PATCH；中途失败会产生部分成功。可考虑服务端批量事务接口。
3. **schema 升级机制缺失**：`CREATE TABLE IF NOT EXISTS` 不会为旧表自动添加新列。下次 schema 变化前应引入 `PRAGMA user_version` 或迁移表。
4. **测试有启动备份副作用**：导入 `server.js` 会立即触发 backup；即使测试 DB 是临时文件，也可能在项目 `backups/` 产生文件。测试端口固定时也可能冲突。
5. **备份文件名精度**：时间戳只到分钟，同一分钟重复启动可能覆盖同名备份。
6. **execution 读取窗口**：`/api/data` 只返回过去 45 天以来的执行记录。日历跳到更早日期时无法看到历史 execution；未来没有上限。
7. **输入验证较轻**：状态枚举、日期格式、ID 类型和 goal 外键没有统一验证，部分非法输入会落到 500。
8. **审计不是事件源**：有些业务写与 audit 不在同一事务，不能依赖 audit 重放或做强一致恢复。
9. **单文件前端可维护性**：全量重载/重绘简单可靠，但功能继续增加时容易形成选择器和共享状态耦合。拆分前应先建立浏览器回归测试，避免为了模块化改变行为。
10. **迁移是破坏式一次性工具**：`2-import.mjs --force` 会移除目标数据库及 WAL/SHM，不可当作日常同步命令。

## 开发时容易踩的坑

- `POST /api/task` 创建日期字段叫 `start`/`end`，PATCH 和数据库字段叫 `start_date`/`end_date`。
- 子树分类在 UI 上通常按根节点语义显示；只改某个子节点 `kind` 可能不产生用户预期的视觉变化。
- `done_at` 是本地日期字符串，不是带时区时间戳。
- `/api/data?archived=1` 才返回归档任务；默认进度计算不包含归档节点。
- 删除 goal 会让任务脱钩，不会删任务；删除任务会因 `ON DELETE SET NULL` 保留 execution。
- `start.bat`、`.env.example`、`server.js` 默认端口和文档必须同步维护。
- 当前仓库公开。真实任务名称可以出现在用户许可的截图里，但数据库、口令和 Notion token 永远不提交。

## 建议的后续开发顺序

1. 提取统一 `inferOpenStatus(task)`，修复自动重开与 execution 重开的状态回落，并补 goal/pool 根任务测试。
2. 给 schema 建立版本迁移机制。
3. 为批量甘特与标签操作增加服务端事务接口。
4. 建立最小浏览器回归测试后，再评估拆分单文件前端。
5. 增加可配置的 execution 历史窗口或按日期读取接口。
